# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

GranitDb is a metadata catalog for databases: it stores descriptions (databases, tables, columns, relations) in a catalog database and exposes them through a REST API and a Blazor WebAssembly UI. **No database server is required**: the catalog defaults to a SQLite file and a database to document can be a plain SQLite file. See `README.md` for configuration and `work-doc/` for the project assessment and the roadmap.

Projects (.NET 10; `GranitDb.sln` at the root holds them all, `api/` and `client/` also keep their own `.sln`):
- `api/` (`GranitDB.API`) — ASP.NET Core Web API (controllers, Swagger in Development, Dockerfile).
- `client/` (`GranitDb.Client`) — Blazor WASM + MudBlazor, PWA service worker.
- `tests/GranitDb.Tests` — xUnit; no external service needed.

## Commands

```bash
dotnet run --project api --launch-profile http    # http://localhost:5105, swagger at /swagger
dotnet run --project client                       # http://localhost:41248 (API URL: client/wwwroot/appsettings*.json)
dotnet test tests/GranitDb.Tests                  # all tests
dotnet test tests/GranitDb.Tests --filter "FullyQualifiedName~SchemaSynchronizerTests"   # one class
```

Target framework: .NET 10 (SDK 10 or newer).

## Architecture

**Catalog access.** `ICatalogRepository` (`api/Data/`) is the only way to read/write the catalog: generic Dapper CRUD driven by `[Table]`/`[NotMapped]` on the models in `api/Models/Descriptions/`, `FindAsync` filters in SQL on a whitelisted property, and `DeleteAsync` cascades manually (database → tables → columns → relations). `InTransactionAsync` hands back a repository bound to one connection/transaction (nestable): the synchronizer and every import run inside it, so they are atomic and fast (one commit instead of one per row) — never loop over single repository calls outside a transaction. `IDbConnectionFactory` opens SQLite (foreign keys enforced via PRAGMA) or SQL Server connections per `Catalog:Provider`.

**Migrations.** The catalog schema is versioned in `CatalogMigrations` (one SQL list per provider, never edit a published migration — append one). `MigrationRunner` applies pending ones at startup (each in its own transaction, version recorded in `SchemaVersion`, concurrent starters tolerated, a catalog newer than the app is refused). `SqlServerBootstrap` waits for the server (up to ~60 s) and creates the database.

**Sources and sync.** `ISchemaConnector` (`api/Connectors/`) reads a source's schema into a `SourceSchema` and never writes to it: `SqliteSchemaConnector` (read-only open, `pragma_table_xinfo` / `pragma_foreign_key_list`) and `SqlServerSchemaConnector`. `SchemaSynchronizer` merges a `SourceSchema` into the catalog: tables/columns/indexes are matched by name (SQL Server tables outside `dbo` are named `schema.table`), hand-written descriptions are preserved, vanished items are deleted, and foreign keys become `Relations` marked `MetaInfo = "auto:fk"` (recreated on each sync; manual relations are untouched). A relation's `FirstId` is the referenced column and `SecondId` the referencing column. **Multi-column relations (migration 12):** a composite foreign key is one relation: its first pair stays in `Relations.FirstId/SecondId`, the next ones are `RelationColumns` rows (`RelationColumnInfo`, position ≥ 1, no FK, cascades by hand in `DeleteAsync`), exposed as `RelationInfo.ExtraColumns` (`[NotMapped]`, filled by `GetRelationsOfDatabaseAsync` and `RelationInfoController.GetT`; `Pairs()` lists all). Connectors set `SourceForeignKey.Constraint` only for composite keys (all pairs share it, in key order); the synchronizer and `SchemaDiffer` group by it. `RelationInput.ExtraColumns` and `DocRelationInput.Extra` carry the other pairs (same table on each side).

**SQL Server sources.** Gated by `Catalog:AllowSqlServerSources` (default true, set false to forbid: the API must not connect to a server chosen by the caller; `GET Capabilities` tells the client). `SqlServerImportController` (`import/sqlserver/test|POST|PUT {id}`) builds the connection string with `SqlConnectionStringBuilder` from `SqlServerConnectionInput` (never string concatenation), reads the schema only (`ApplicationIntent=ReadOnly`), filters by chosen schemas (`SourceSchemaFilter`) and stores `{ConnectionString, Schemas}` as JSON encrypted by `ISecretProtector` (Data Protection, keys in `Catalog:KeysDirectory`, default `DataDirectory/keys`) in `Databases.SourceSecret` (migration 9, `[JsonIgnore]`) with a non-secret `SourceLabel`. `ReadSourceAsync` serves both resync and preview for SQLite and SQL Server; an undecryptable secret gives a "saisissez-la de nouveau" error, a database read only through `StartupSources` has no secret and cannot be resynced by the API. `SqlServerErrors.Describe` maps driver error numbers to instructions (test 4060 before 18456: an unknown database raises both) and a connection failure during `/test` is a 200 with `ok:false`, not a 400. **Output DTOs:** `DatabaseView` (no `SourcePath`, no secret, `CanResync`), `SyncSummaryView`, `ImportView` — never return `DatabaseInfo` or `SyncResult`/`ImportResult` directly (`BaseDbInfoController.View` is the hook). `ModifyAsync` takes the caller's identity (`Actor` = authenticated `User.Identity.Name`, null today) for `History.ChangedBy`; tests simulate a caller with the `X-Test-User` header (a test-only `IStartupFilter` in `KestrelApiFactory`).

**Domain display settings & deletions.** `DomainInfo.ShowNeighbors` (default false: the domain diagram draws only the domain's own tables, neighbours from other domains in dashed "frontier" nodes only when true) and `DomainHiddenRelations` (relations not drawn in that domain; no FK on the relation, cleaned by `DeleteAsync` cascades) arrive with migration 10 and are set through `PUT DomainInfo/{id}/settings` (absent fields untouched; `DomainInput.ShowNeighbors` is nullable so a rename keeps it). `DELETE DatabaseInfo/{id}` goes through `DatabaseImportService.DeleteDatabaseAsync` (cascade + a `Deleted` row in `History` via `RecordHistoryAsync` + removal of the kept source file); the client asks to retype the name (`DeleteDatabaseButton`). `POST import/sqlite/{id}/preview` diffs a replacement file without writing or keeping it. `POST import/documentation/{databaseId}` (`DocumentationImportController`) fills empty descriptions, domains (with an optional layout) and manual relations from an external documentation, matching by name (a domain may carry `drawnRelations`: the other relations between its tables are stored as hidden for that domain; `work-doc/herakles-tools/convert-dataedo.mjs` builds its JSON from a Dataedo HTML export; `work-doc/herakles/` is git-ignored).

The database page groups its documentation tools (new table, documentation assistant, suggested relations, profiling) in one "Documenter" menu, like "Exporter"; the diagram page keeps its own table picker (the sidebar panel that duplicated it was removed). Edit files with CRLF through tools that preserve line endings; in this repo's shell, long here-documents can break the bash tool — write scripts with the Write tool.

**Audit and webhooks (migration 11).** `AuditMiddleware` (registered before the exception handler) writes one `AuditLog` row per write request and per `/export/` call (actor, method, path without `/api/v1`, status, controller, route id, IP; never the body); `GET Audit` filters/pages it. `Webhooks` stores subscriptions (secret encrypted with `ISecretProtector`, never returned); `DatabaseImportService.NotifySchemaChange` enqueues `schema.changed` on resync/replace/startup sync when tables, columns or indexes changed, and `WebhookDispatcher` (a `BackgroundService`) POSTs it with retries and an `X-GranitDb-Signature: sha256=` HMAC. Targets that are loopback/private are refused at registration and again at connection time (`WebhookUrlPolicy`, `ConnectCallback`) unless `Webhooks:AllowPrivateHosts`.

**Authentication and roles (milestone 6).** `Auth:Enabled` (default false, dev stays open) switches on `AuthSetup.AddGranitAuth` (`api/Security/`): a cookie session (`granitdb.session`, 401/403 instead of redirects) fed by GitHub (`AddOAuth`, endpoints overridable for GitHub Enterprise and for tests; `/user`, plus `/user/orgs` and `/user/teams` only when `Roles:*Groups` are configured) and by any number of generic OpenID Connect providers declared in `Auth:Providers:<name>` (authority, client id/secret, scopes, claim names for login/name/avatar/groups; code flow + PKCE, `OnTicketReceived` builds the principal). Both build the same principal (name = login, `ClaimTypes.Role`, `granitdb:name|avatar|provider` claims) after `RoleResolver.Resolve` (logins `login` or `provider:login`, groups, `DefaultRole`; highest role wins; `None` = refused: the user is redirected to the return URL with `auth_error=refused`, any other failure `failed`, detail only in the server log; the OAuth handler swallows exceptions of `OnCreatingTicket` but not of OIDC `OnTicketReceived`, which therefore answers itself). Roles are computed at sign-in and live in the cookie. `AuthSetup.Validate` refuses to start with auth on but no provider or no admin. `RoleAuthorizationFilter` (a global MVC filter) enforces roles: reads need Reader, writes Editor, `[MinimumRole(Role.Admin)]` on `Audit`, `Webhooks`, `SqlServerImport` and `import/sqlite/local`; `[AllowAnonymous]` on `AuthController` (`GET Auth/me` = `SessionView`, `GET Auth/login/{provider}?returnUrl=` ignored by OpenAPI, `POST Auth/logout`); every write must carry `X-GranitDb-Client` (CSRF guard: forces a CORS preflight). `UseAuthentication` runs before `AuditMiddleware`, so `Actor`/`History.ChangedBy` become the login. `Cors:AllowedOrigins` (credentials) replaces the permissive policy; empty = all origins without cookies; the login return URL must be a path or one of those origins. `IsPublic` databases are readable without an account through `PublicAccess` (a whitelist of read actions resolved to a database, unknown/private = 401; `GetAllT`/`Search` are filtered by their controllers; visitors never see `SourceLabel`; only admins can set `IsPublic`, others keep the stored value; `Auth:AllowPublicDatabases`; `SessionView.AllowAnonymousRead` makes the client open read-only as a "visitor"). Secrets: `SecretReference` (`env:NAME`, `file:/path`) for `StartupSources` connection strings and the key certificate password; `Catalog:KeysProtection` None/Dpapi/Certificate encrypts new Data Protection keys. Not done: role changes without re-login, a remote key vault. **Client:** `AuthState` (scoped, `AddGranitWorkspace`) loads `GET Auth/me` in `MainLayout` (no page renders before it answers); `NeedsLogin` shows `LoginScreen` (one button per provider, `LoginUrl` = navigation to the API), `UserMenu` shows the account/role and logout; `CanEdit`/`IsAdmin` hide import, delete, resync, tags/domains, audit, webhooks, SQL Server entries and make `InlineText` read-only for readers; `Client.Unauthorized` (a static event raised by every 401) sends an expired session back to the login screen; `SessionHandler` in `Program.cs` sends cookies (`SetBrowserRequestCredentials(Include)`) and the CSRF header on writes. Tests: `AuthTests.cs` (fake GitHub and signed-RS256 fake OIDC provider on local Kestrel ports, full redirect flows with a cookie-keeping `HttpClient`), `ClientAuthTests.cs` (bUnit).

**Server engines (milestone 8).** `ServerEngines` (SqlServer, PostgreSql, MySql: type name, default schema, default port, schema/integrated-auth support, `SchemaOf`/`Qualify`) is the registry of client/server sources; `DatabaseInfo.Type` holds the engine, `ISchemaConnector`/`IColumnProfiler` are looked up by it. `PostgreSqlSchemaConnector` (Npgsql, reads `pg_class`/`pg_attribute`/`pg_constraint`/`pg_index`, `public` tables keep their bare name, positions renumbered from 0 because `attnum` has gaps) and `MySqlSchemaConnector` (MySqlConnector, `information_schema` of `DATABASE()`, no schemas) set `SourceForeignKey.Constraint` for composite keys like the others. `ServerConnectionInput` (was `SqlServerConnectionInput`; `Engine`, default SqlServer; builds the string with each driver's builder: PostgreSQL `Options=-c default_transaction_read_only=on`, MySQL `VerifyCA` unless trusted) feeds `DatabaseImportService.TestServerAsync/ImportServerAsync/ReplaceServerConnectionAsync` (the stored encrypted `SourceConnection`, `ReadServerSourceAsync`, `ResolveSourceAsync` are engine-generic; one switch `Catalog:AllowSqlServerSources` covers all three). Routes: `import/server` (any engine) and the original `import/sqlserver` (forces SqlServer); the client facade picks by engine (`TestServerAsync` …). `ConnectSqlServer.razor` (routes `/import/sqlserver` and `/import/server`) has the engine menu (hidden when editing: the engine of an existing database cannot change). Tests run against PostgreSQL/MySQL containers (`PostgreSqlFixture`, `MySqlFixture`, skipped without Docker like SQL Server's).

**Scheduled sync (migration 14).** `Databases.SyncIntervalMinutes/LastSyncAt/LastSyncOk/LastSyncError` (exposed in `DatabaseView`). `PUT DatabaseInfo/{id}/schedule` (`ScheduleInput.IntervalMinutes`, 0 = off; admin; needs a source to reread and `Catalog:AllowScheduledSync`; minimum `Catalog:MinSyncIntervalMinutes`). `SyncScheduler` (`BackgroundService`, tick `Catalog:SchedulerTickSeconds`, first pass after 10 s) calls `RunDueAsync(now)`: due = interval set, source present, `LastSyncAt` null or older than the interval; each due database goes through `ResyncAsync` (which records success and enqueues `schema.changed`); a failure is recorded with its reason (`RecordSyncAsync`) and enqueues the `sync.failed` webhook event (`NotifySyncFailed`), and is not retried before the next interval; one pass at a time (semaphore), each relecture bounded by `Catalog:SyncTimeoutSeconds`. Client: `DatabaseDetail` shows a "Synchronisation automatique" menu (admin changes it, others read) and the last result.

**Column profiling (migration 13).** `Catalog:AllowProfiling` (default false: the only feature that reads source *data*). `IColumnProfiler` (`SqliteColumnProfiler` read-only, `SqlServerColumnProfiler` with `ApplicationIntent` from the stored connection) makes the source compute `COUNT(*)`, `COUNT(col)`, `COUNT(DISTINCT col)` in batches of 60 columns (no `DISTINCT` for text/ntext/image/xml/CLR types: `DistinctCount` null); only counts come back. `ColumnProfilingService` resolves the source through `DatabaseImportService.ResolveSourceAsync` (same checks as the schema read), stores one `ColumnProfiles` row per column (`ColumnProfileInfo`, replaced on each run, cascaded by hand in `DeleteAsync` for database/table/column), refuses views, and for a whole database goes through tables oldest-profile-first up to `ProfilingMaxTables` (result `ProfileRunView`: profiled / failed with reasons / remaining). `ProfileKind.Of` labels a column (empty, constant, unique, low ≤ 20 values or < 1 %, high, unknown). Routes: `GET TableInfo/{id}/profile` (Reader, also readable anonymously on public databases), `POST TableInfo/{id}/profile` and `POST DatabaseInfo/{id}/profile` (`MinimumRole(Admin)`). Client: `DatabaseDetail` loads a table's profile when it opens (`GetTableProfileAsync`, absent until profiled), adds a "Profil" column and a "Profiler la table" button (`CanProfile` = capability + admin), and a database-level "Profiler les colonnes" button. Tests: `ColumnProfilingTests.cs` (service on a real SQLite file, API), `ClientProfilingTests.cs`. Exports do not include profiles yet.

**Relation detection (milestone 13, lot A; migration 15).** `RelationCandidates.Find` (pure, catalog only) matches a column name (`Stem`: `client_id`/`id_client`/`clientId`/`fk_client`/`client_code` minus the id markers; a role prefix such as `billing_client_id` matches by suffix) to a real table (`TableWords`: no `tbl_`/`t_` prefix, singular) whose single-column primary key or single-column unique index has a compatible `TypeFamily`; pairs already linked either way, or already referenced from that column to that table, or decided before, are skipped. `RelationDetectionService` (same switch as profiling, `Catalog:AllowProfiling`) checks each candidate at the source through `IColumnProfiler.CheckInclusionAsync` (`ProfileQuery.BuildInclusion`: three scalar sub-queries, never an aggregate over `NOT EXISTS`, SQL Server refuses it; counts only: non-null values, orphans, parent rows), scores it (name 40/28 + type 10/5 + unique target 15/12 + inclusion 30/20/10, minus 25 when the target has fewer than 20 rows, dropped under 40 or above 5 % orphans, up to `RelationDetectionMaxChecks` candidates per run) and stores `RelationSuggestions` rows (`RelationSuggestionInfo`: child/parent column and table ids, score, reasons one per line, counts, status pending/accepted/rejected; a run replaces the pending ones and keeps the decided ones; cascades by hand in `DeleteAsync`). Accepting creates a manual `RelationInfo` (`FirstId` the referenced column) with `MetaInfo = "detected"` (`RelationDetectionService.DetectedMarker`; the synchronizer keeps manual relations). Routes live on `DatabaseInfoController` (`relation-suggestions`, `detect` is admin-only); client page `RelationSuggestions.razor` (`/databases/{id}/relations`). **Search by values (`POST …/relation-suggestions/detect?byValues=true`, button "Détecter aussi par les valeurs"):** the name rule misses columns whose name does not say the table (`code_fab` → `fabricants`). `RelationCandidates.FindByValues` pairs every comparable column (text/number/guid, not long text/binary/xml) with the single-column unique columns of the same type family of other tables, ranked by affinity (same normalised name as the target column, `Key`, and not a generic one: 25; a shared significant word with the column or table: 12; none: 0, only tried when the base has at most `BlindTableLimit` = 80 tables and never for a primary key); a child longer than the target column is skipped. Each candidate first goes through a quick test on a sample (`InclusionCheck.SampleSize` = `Catalog:RelationDetectionSampleSize` distinct values: `SELECT DISTINCT … LIMIT n` / `TOP (n)` on SQL Server, orphans over 5 % or fewer than 5 values drop it, and without any name affinity fewer than 20 distinct values too), then the usual full check and scoring (name part = affinity); at most `Catalog:RelationDetectionMaxValueChecks` (20000, within `Catalog:RelationDetectionMaxValueSeconds` = 300 s) per run, the rest counted as skipped. Still only counts leave the source. Not done: composite keys, "detected" badge in the diagram/exports, server engines tested only against SQLite.

**AI base (milestone 13, lot B).** `Catalog:AllowAi` (default false) + `Ai:*` (`AiOptions`: Endpoint default `http://localhost:11434/v1`, Model `qwen3:4b-instruct`, ApiKey via `SecretReference`, TimeoutSeconds, MaxConcurrent, AllowRemote, MaxRequestChars, MaxOutputTokens, Language). `IAiProvider` (`OpenAiCompatibleProvider`, singleton owning its `HttpClient` and a `SemaphoreSlim`; tests inject a `FakeAiServer` handler) speaks only `/chat/completions` and `GET /models`. `AiRequest(System, User, Schema?, Validate?)`: with a schema it sends `response_format: json_schema`, parses the answer as a JSON object, runs `Validate`, retries once telling the model what was wrong, then throws a `GranitExceptions` (400); `<think>` blocks are stripped. Guardrails: `Endpoint()` refuses non-http(s), credentials/query in the URL, and a non-local host that is not https unless `AllowRemote` (compose sets it: the `ollama` service is plain http on the Docker network); size/concurrency/timeout limits; the log line carries model, tokens and duration, never content. `AiController` (`Ai/status`, `Ai/test`, admin only), `CapabilitiesView.AllowAi/AiModel`, client `AiPanel` on the Manage page. Compose profile `ai` (`ollama` + one-shot `ollama-pull` of `AI_MODEL`). Lot C builds prompts on top: whitelist of fields and sensitive-column exclusion are its job.

**Documentation assistant (milestone 13, lot C; migration 16).** `DescriptionAssistant` (singleton) turns undescribed elements into `DescriptionSuggestions` rows (`DescriptionSuggestionInfo`: Kind description|sensitive, TargetType database|table|column|relation, Text, Model, Uncertain, Status pending|accepted|rejected; cascades by hand in `DeleteAsync`). `SuggestTableAsync` builds one prompt per table (ColumnsPerPrompt 15): whitelist only (names, types, key/nullability, neighbours' descriptions, up to 3 style examples, profile kind); sensitive columns and relations touching them never go out; the answer is schema-constrained (`table` + `columns[]`), names the model invented are dropped, text cleaned (`Clean`, 300 chars), `IsCryptic` forces `Uncertain`. Relations are described by batches of 10 (index in the prompt), the database from its table names. A batch (`StartJobAsync`, one per database, in-memory `Job` with progress/cancel, stops after 3 consecutive failures) skips elements already described, pending or rejected, so it is resumable; `SuggestAsync` (the "Suggérer" button) regenerates one element but refuses an already described one. `AcceptAsync` writes through `ModifyAsync` only if the description is still empty (`Write<T>`), with `ChangedBy = "actor (proposé par model)"`; sensitive suggestions come from `SensitiveRules` (whole-word name rules, no model) and accepting sets `IsSensitive`. `AcceptConfidentAsync` never takes uncertain ones. Routes: `DescriptionSuggestionsController` (`database/{id}`, `generate`, `job`, `job/cancel`, `suggest`, `detect-sensitive`, `{id}/accept|reject`, `accept-confident`; Editor role, not public). Client: `DocumentationAssistant.razor` (`/databases/{id}/documentation`, polls the job every 2 s) and `SuggestButton.razor` under empty table/column descriptions. Tests use `ScriptedAiServer` (a fake model that reads the prompt). Not done: glossary, suggested domains, model evaluation, Ctrl+K entry.

**Exports.** `GET DatabaseInfo/{id}/export/markdown|csv` (`DocumentationTextExporters`; CSV escapes leading `=+-@`) and `export/xlsx` (`XlsxExporter`: hand-written OOXML zip, sheets Tables/Colonnes/Relations/Index, inline strings never formulas) share `HtmlDocumentationExporter.LoadAsync`. `GET DatabaseInfo/{id}/export/html` (`HtmlDocumentationExporter`) returns one self-contained HTML file (data embedded as JSON, inline CSS/JS, hash router) styled like the Dataedo export in `work-doc/herakles` (blue side nav with domain/table tree, breadcrumb, summary, columns, relations, indexes, plus SVG ERDs drawn in the page script: one per domain from the saved plan minus hidden relations, one neighbourhood diagram per table); the single "Exporter" menu is on the database page (HTML, Markdown, CSV, Excel, PDF); PDF has no server renderer: the HTML export has a printable view (`#/print`, one table per page) that the menu opens in a tab for the browser's "save as PDF".

**OpenAPI contract and generated client.** Swagger (`AddSwaggerGen` in `Program.cs`) describes only `api/v1/` routes, every operation named `Controller_Action` (generic base actions lose their trailing `T`), and `Swagger/ResponseTypesFilter` declares each operation's response type (actions return `IActionResult`, so nothing else says what they answer; add new routes there). `client/api/openapi.json` is the committed contract; `OpenApiContractTests` fails when it no longer matches the API. After any API route/type change run `scripts/generate-client.ps1` (writes the contract via that test with `GRANITDB_UPDATE_OPENAPI=1`, then NSwag generates `client/api/Generated/GranitApiClient.cs` — one client per controller in `GranitDb.Client.Generated`, grouped by `GranitApi` — and `GranitApiContracts.cs` — the DTOs and client interfaces, in `GranitDb.Client.Models`). The UI's models are those generated DTOs (`DatabaseView`, `TableInfo`, `ColumnInfo`, `DomainView`, `ImportView`, `CapabilitiesView`, `SqlServerConnectionInput`…, lists are `List<T>`); `client/Models/CatalogModels.cs` only adds partial members (default values, `RelationInfo.Pairs()`, `SearchHit.Href`) and the UI-only types (`Page<T>`, `AuditFilter`, `WebhookForm`). Never edit the generated files. `client/api/Client.cs` is the UI's facade over the generated clients: same method names as before, errors turned into `ApiException`/`HttpRequestException`, optional reads falling back to empty values, header totals (`X-Total-Count`, `wrapResponseMethods` in the script) and file exports (raw `HttpClient`: the contract does not describe files as data). A generated client is strict about status codes (201 for creations, 204 for deletions, declared in `ResponseTypesFilter`): test doubles must answer like the API, and `ClientAgainstApiTests` runs the facade against the real API.

**Import.** `DatabaseImportService` handles SQLite uploads (`POST /import/sqlite`, `PUT /import/sqlite/{id}`, `POST /import/sqlite/local` behind `Catalog:AllowLocalPaths`) and `POST /DatabaseInfo/{id}/sync`. Uploaded files are checked (SQLite header, size), stored in `<DataDirectory>/sources/` under a server-generated GUID name, and only re-read from that folder unless local paths are allowed. `Catalog:StartupSources` syncs declared sources at startup.

**API surface.** Every controller is routed under `api/v1/` and, as a legacy alias, without prefix (two `[Route]` attributes; the client uses `api/v1`). `BaseDbInfoController<T, TInput>` gives GET all (optional `skip`/`take` paging with `X-Total-Count`, sorted by name, plus the query filters declared by each controller in `Filters`: parameter → property + `FilterMode` Equals/Contains/Bool, applied in SQL by `ICatalogRepository` through `CatalogFilter`) / GET id / POST / PUT / DELETE. POST/PUT bodies are `InfoInput<T>` DTOs (`api/Models/Inputs/`, DataAnnotations validated by `[ApiController]`), never the entity: server-managed fields (e.g. `DatabaseInfo.SourcePath`) are absent from them and a PUT goes through `ICatalogRepository.ModifyAsync` (read → `input.Apply` → update), which also appends every change of `Description`/`MetaInfo` to the `History` table (migration 7, no FK so it survives deletions; the synchronizer uses `UpdateAsync` and writes no history). `TableInfoController` overrides GET to include columns (by `Position`), indexes and relations, adds `GET TableInfo/database/{id}` (filters + paging) and `{id}/columns|indexes|relations`. `ImpactController` (`Impact/table/{id}`, `Impact/column/{id}`) walks the relations breadth-first with `ImpactAnalyzer` (dependents = who references me, dependencies = who I reference, within the element's database). `HistoryController` lists the history (tracked fields: `Description`, `MetaInfo`, `IsSensitive`). Every entity also has `PUT {id}/documentation` (description + MetaInfo only, via `ModifyAsync`); `ColumnInfoController` adds `PUT {id}/sensitivity`. `RelationInfoController` validates manual relations (columns exist, same database, no duplicate in either direction) and protects the `auto:fk` marker (`RelationInput.ResolveMetaInfo`); the synchronizer re-creates detected relations with their previous Id, type and description. Governance entities (`api/Models/Descriptions/GovernanceInfo.cs`, migration 8): `DomainInfo` + `DomainTableInfo` (table↔domain link carrying the remembered X/Y; `DomainInfoController` exposes `database/{id}`, `tables/{tableId}` with `?moveFrom=`, `layout`), `TagInfo` + `TagLinkInfo` (polymorphic link, type = database/table/column; `TagInfoController.attach`), all with their own Id so the generic repository works; `DeleteAsync` cascades their links manually, and `FilterMode.In` (`CatalogFilter.In`) backs the `domainId`/`tag` filters (`LinkFilters`). `CompletenessController` computes described/total per table (blank descriptions do not count; undescribed sensitive columns are counted apart). `SchemaDiffer` (used by `POST DatabaseInfo/{id}/sync/preview`) mirrors the synchronizer's matching rules without writing, and flags removals that would lose documentation — keep the two in step when changing either. `GranitExceptionHandler` maps `GranitExceptions` to 400 and DB constraint violations to 409 (ProblemDetails).

**Client.** The UI is a workspace: `Layout/MainLayout.razor` hosts `Explorer` (tree of databases → tables → columns with domains and favorites; roving tabindex, arrow keys via `granitdb.moveTreeFocus` in `wwwroot/js/granitdb.js` (no inline script: the nginx CSP forbids it; the HTML preview opens the API URL `export/html?inline=true`, never a blob)), `TabStrip` (one tab per open page; tabs are buttons, not links, so a middle click does not also open a browser tab), `DetailPanel` (selection from the explorer), `CommandPalette` (Ctrl+K), `ToastHost`. Shared state lives in scoped services registered by `AddGranitWorkspace()` (`client/Workspace/`): `WorkspaceState` (tabs keyed by path — the query string does not make another tab —, favorites, selection, panels, persistence as JSON in `localStorage` `granitdb.workspace`; `CatalogChanged(databaseId, source)` tells every view to reread, the emitter passes itself as `source` to skip its own event; drawer open state set by the layout's breakpoint is **not** remembered, only user toggles — `SetExplorerOpen(open, remember)`), `Notifier` (toasts, success messages with an optional undo; errors stay inline next to what failed) and `CatalogCache`. Pages tell the workspace their tab title with `Workspace.Describe(Navigation.Uri, title)`. A table tab is `DatabaseDetail` on `/databases/{id}/tables/{table}` (`TableRoute`, optional `?column=` highlight), the database page being the same component without it. `InlineText` saves on blur/Enter, Escape cancels, and shows an undo toast unless `Silent`. Razor attribute values cannot contain escaped quotes (`\"`): use constants or helper methods. In bUnit, render components that need the workspace with `ShellTestBase` (fake API + services); `MainLayout` has its own `MudPopoverProvider`, so do not render another one next to it. `client/api/Client.cs` wraps `HttpClient` (registered in `Program.cs` from `ApiBaseUrl`): paged list (`X-Total-Count`), tables, upload, sync, global search. Pages: `Databases.razor` (paged list + drop zone), `DatabaseDetail.razor` (`?table=<id>` expands and scrolls to a table), `Search.razor` (`/search?q=`, results grouped by kind), `Manage.razor` (`/manage`: rename, colour and delete tags and domains), `Audit.razor` (`/audit`: filtered, paged audit log) and **Input dialogs** (`client/Components/Dialogs/`: `RelationDialog`, `DomainDialog`, `WebhookDialog`, `ConfirmDialog`, opened with `DialogHelper.ShowFormAsync/ShowDataAsync` from `IDialogService`; `MainLayout` hosts the `MudDialogProvider`, bUnit tests render their own and read dialog content from it, not from the page; popover/dialog content is never in the page's DOM) — they validate before sending, show server errors inline and close with Escape/Cancel without saving. `Webhooks.razor` (`/webhooks`: create/edit/test/delete, list deliveries; the API refuses a webhook with a plain-text 400, read by `Client.EnsureTextAsync`), `ConnectSqlServer.razor` (`/import/sqlserver[?id=]`: test then import, or replace the connection of database `id`; hidden behind `Capabilities`), `Diagram.razor` (`/databases/{id}/diagram`: domains panel, table picker, zoom, impact panel, SVG/PNG/Mermaid export; in a domain view the checkboxes mean membership, tables outside the domain but related to it are drawn as dashed *frontier* nodes (`ErNode.IsFrontier`, rows reduced to the related columns), node positions are saved per domain; dragging a table to a domain works both from the picker list (HTML5 drag-and-drop) and out of the SVG (`ErDiagramView.OnDragLeave` → page-level `_draggedTable` → `pointerup` on the domain card)). `DatabaseDetail.razor` edits in place through `Components/InlineText.razor` and `TagEditor.razor` (child components call the page through plain `Func`s, so the page must call `StateHasChanged()` itself after saving), uses `Components/NativeSelect.razor` for dropdowns (`MudNativeSelect` does not bind here), and shows the sync preview inline before applying (no dialog). The diagram is split in `Diagram/ErDiagram.cs` (pure model: edge routing, `ToSvg`, `ToMermaid`; nodes are mutable X/Y) whose auto-layout is `Diagram/ErLayout.cs` (Sugiyama: connected components packed on shelves, cycle removal, layering tightened toward the dominant side, one dummy per crossed layer so long links get waypoints, barycenter + transpose ordering with exact crossing count and several starts, heights by weighted isotonic regression so a table faces the columns that link it; `ErDiagram.Route` draws a long link through its waypoints only while both end tables sit where the layout put them; `Crossings()` is the count at the last layout) and `Components/ErDiagramView.razor` (interactive SVG: drag, click = select; Razor reserves the `<text>` tag, so SVG text is built by hand in `Txt`; string parameters need `@` — `Param="@x"`, not `Param="x"`); downloads go through `granitdb.download|downloadPng|copyText` in `wwwroot/js/granitdb.js` (no inline script: the nginx CSP forbids it; the HTML preview opens the API URL `export/html?inline=true`, never a blob). `MainLayout.razor` holds the global search box (Enter navigates), the light/dark toggle (persisted in `localStorage` under `granitdb.theme`, system preference by default) and the breadcrumbs live in each page. Search is `GET /Search?q=` -> `ICatalogRepository.SearchAsync` (LIKE with `!` as escape character, per-kind limit; besides bases, tables, columns and indexes it finds domains, and the tables of a matching domain or the bases/tables/columns carrying a matching tag, with `SearchHit.Via` giving the reason; the client limits a search started from a database page to that database through `/search?q=…&db=…`). Client models are generated from the API contract (see above).

## Tests

SQL Server tests (`SqlServerTests`, via Testcontainers) are skipped when Docker is unavailable unless `GRANITDB_REQUIRE_SQLSERVER=1` (CI sets it); the first run pulls the SQL Server image (~1.5 GB). Docker: `docker compose up --build` (SQLite) or `docker compose --profile sqlserver up --build` (needs `.env`, see `.env.example`); both Dockerfiles use the repo root as build context.
bUnit tests use `BunitContext` by composition + `IAsyncLifetime` (MudBlazor services are async-disposable only), never by inheritance.

`KestrelApiFactory` runs the API on a real Kestrel port instead of the in-memory TestServer. Test catalogs live in temp directories (`TestCatalog`); call `SqliteConnection.ClearAllPools()` before deleting SQLite files on Windows.

## Conventions

- Code comments and user-facing messages are mostly in French.
- The default data directory is `granitdb-data` (not `data`: `Data/` is a code folder and Windows paths are case-insensitive).
- Git: do not add Claude as author or co-author in commits (user instruction); work on a feature branch, not `main`.
